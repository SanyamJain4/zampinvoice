## Other automated tests
* **Parsing/OCR** – native rows rebuilt per baseline; multi-page table; image-only PDF really has no text layer and is read via OCR.
* **Validation** – normalisation never invents; `Decimal` exactness; tolerance boundary (exactly 1.00 % passes); fixed-amount tolerance.
* **Vendor matching** – priority order, aliases, normalised names, inactive/blocked, conflicting tax ID/name, near-miss names are only suggestions.
* **Workflow** – idempotent re-processing; duplicate file never consumes PO balance twice; same number from another vendor is not a duplicate; suspicious near-duplicate → review;
  **concurrency** (6 racing invoices → exactly 2 approved; 3 racing same-number invoices → 1 approved, 2 rejected); corrupt PDF / LLM outage → `PROCESSING_ERROR` (not rejection) and retry works;
  hallucinated invoice number caught by R15; prompt injection cannot change the decision; stages persisted with timestamps/data; DB persistence & audit events; SSE stream.
* **Review** – correction → re-validation → explicit approval (corrected data is never auto-approved); hard controls cannot be bypassed (R04, R05, R02, R10, duplicates, blocked vendors); soft overrides are audited; reject; clarification.
* **API** – upload validation (signature, empty, size, path-traversal filename), pagination/filters, master data, dashboard maths, audit, health/settings (no secrets), samples & reset.
* **LLM client (mocked HTTP)** – success, retry-then-success, bounded retries, timeout, 401 not retried and key never echoed, invalid JSON retried, missing key message.
* **Frontend** – formatting utils, decision banner (approved vs processing error), badges, timeline status mapping.
